# Aion MVP Implementation Plan

> **Historical document.** This is the original plan for a sleep-focused face. The current face is an analog design with steps and intensity-minute rings, described in the [README](./README.md#the-face). The plan is kept for its notes on the Forerunner 965 and its API limits.

## Goal

Build the smallest useful version of **Aion**, a clean, sleep-oriented Garmin watch face for the **Garmin Forerunner 965**.

This document is the implementation handoff. The next implementation pass should follow this scope closely and avoid adding features that are not required for the MVP.

## Target device

- Garmin Forerunner 965 only
- 454 x 454 round AMOLED display
- Connect IQ watch face app
- Target the device/API level supported by the current Garmin SDK for the Forerunner 965
- Develop in VS Code with Garmin's Monkey C extension

## Important API constraint

The original direction for Aion includes sleep information.

For the MVP, **do not implement Sleep Score**.

As of October 2026, Garmin's Connect IQ compatibility page lists the Forerunner 965 at **API level 5.2**. Garmin's `COMPLICATION_TYPE_SLEEP_SCORE` was introduced at **API level 6.0.2**.

The Forerunner 965 does support the Complications API itself, including metrics such as:

- Body Battery
- Heart rate
- Battery
- Steps

Therefore the MVP should use **Body Battery as the primary sleep/recovery-oriented metric**.

If a future SDK/device firmware exposes Sleep Score to the Forerunner 965, it can be added later without changing the basic visual design.

## MVP display

Use a pure black background for AMOLED.

The active/high-power face should display:

1. **Time**
   - Large and central
   - Hours and minutes only
   - Respect the watch's 12/24-hour setting
   - No seconds in the MVP

2. **Date**
   - Small text directly beneath or above the time
   - Example: `FRI 02 OCT`

3. **Body Battery**
   - Short label such as `BB`
   - Numeric value when available
   - Show `--` if Garmin returns no value

4. **Heart rate**
   - Short label such as `HR`
   - bpm value when available
   - Show `--` if unavailable

5. **Steps**
   - Current daily step count
   - Compact formatting is acceptable if needed, for example `8.4k`

6. **Watch battery**
   - Percentage
   - Example: `82%`

### Suggested layout

Keep the first version visually simple:

```text
              BB 72

             12:36
           FRI 02 OCT

       HR 58   8.4k   82%
```

The exact pixel positions can be adjusted in the simulator, but the hierarchy should remain:

- time is dominant;
- Body Battery is the main recovery metric;
- secondary metrics sit around the edges/bottom;
- no decorative clutter.

## Explicitly out of scope

Do not add these in the MVP:

- Sleep Score
- sleep stages
- sleep duration
- weather
- notifications
- calendar
- phone/network communication
- settings screens
- user-selectable colors
- user-selectable complications
- touch interactions
- animations
- custom fonts
- second hand / seconds display
- multiple Garmin devices
- Connect IQ Store publishing
- analytics
- persistence unless the SDK scaffold requires it

The MVP is successful when it can be built, run in the simulator, sideloaded to the user's Forerunner 965, selected as the active watch face, and display the required data.

## Proposed project structure

Use the normal Garmin Connect IQ Watch Face project structure generated by the Monkey C extension.

Expected shape:

```text
aion/
├── README.md
├── MVP_PLAN.md
├── monkey.jungle
├── manifest.xml
├── source/
│   ├── AionApp.mc
│   └── AionView.mc
├── resources/
│   ├── drawables/
│   └── strings/
└── .gitignore
```

Keep the source small. Prefer direct drawing in `AionView.mc` over building a large XML layout system for this MVP.

## Implementation steps

### 1. Scaffold the Connect IQ project

Create a Garmin Connect IQ **Watch Face** project in the repository root.

Requirements:

- App name: `Aion`
- App type: Watch Face
- Supported product: Forerunner 965 only
- Use the SDK/API level supported by the Forerunner 965
- Keep generated resources minimal

Do not create a second nested project directory if the repository itself can be the project root.

### 2. Add safe Git ignores

Create a `.gitignore` that excludes generated build output and developer signing keys.

At minimum, ignore:

```gitignore
bin/
*.prg
*.iq
*.debug.xml
*.der
*.pem
```

Never commit the Garmin developer key.

### 3. Implement the app entry point

Create the normal `Application.AppBase` subclass.

It should:

- return the Aion watch-face view from `getInitialView()`;
- contain no unnecessary application logic;
- contain no network/background services.

### 4. Implement the watch-face view

`AionView` should extend `WatchUi.WatchFace`.

Responsibilities:

- clear the screen to black;
- calculate positions based on the device context width/height;
- draw time and date;
- retrieve and draw the four data values;
- handle missing data without crashing;
- support high-power and low-power states.

Use Garmin/system fonts for the MVP.

### 5. Time and date

Use Garmin's system/time APIs.

Requirements:

- hours + minutes;
- leading zero where appropriate;
- honor 12/24-hour device preference;
- date format `EEE DD MMM` or a visually equivalent compact uppercase form.

Do not add seconds.

### 6. Body Battery

Use the Garmin `Toybox.Complications` API.

Request the built-in Body Battery complication:

- `COMPLICATION_TYPE_BODY_BATTERY`

Requirements:

- show the numeric value when present;
- show `--` for null/unavailable values;
- do not assume the simulator always supplies a real Body Battery value.

This is the primary Aion/recovery metric in the MVP.

### 7. Heart rate

Prefer the built-in Garmin complication:

- `COMPLICATION_TYPE_HEART_RATE`

Requirements:

- display bpm as a number;
- show `--` when unavailable;
- avoid continuous sensor activation or any approach that materially increases power usage.

### 8. Steps

Use `Toybox.ActivityMonitor.getInfo().steps`.

Requirements:

- display today's step count;
- allow compact formatting when the number is large;
- handle unavailable data safely.

### 9. Watch battery

Use `Toybox.System.getSystemStats().battery`.

Requirements:

- round to a whole-number percentage for display;
- append `%`.

### 10. AMOLED / low-power behavior

The Forerunner 965 is an AMOLED device.

Implement `onEnterSleep()` and `onExitSleep()` cleanly.

For the MVP:

- high-power mode: draw the full face;
- low-power/always-on mode: use a deliberately reduced display;
- simplest acceptable low-power view: black background plus hours/minutes only;
- avoid seconds, timers, animations, and unnecessary redraws.

Do not attempt fancy partial-update animation in the MVP.

The implementation should respect Garmin burn-in/power rules rather than trying to keep the full bright face permanently visible.

### 11. Defensive rendering

No missing Garmin metric should crash the watch face.

For Body Battery and heart rate:

- null -> `--`

For any unexpected retrieval error:

- keep rendering the clock;
- degrade the affected metric to `--`.

The time display is the only truly mandatory runtime element.

### 12. Simulator validation

Before physical-device testing:

1. Open a `.mc` source file in VS Code.
2. Run without debugging.
3. Choose Forerunner 965.
4. Confirm:
   - correct 454x454 round layout;
   - nothing is clipped at the round edges;
   - time changes correctly;
   - date is readable;
   - null complication values render as `--`;
   - no runtime errors appear;
   - low-power transition does not break rendering.

### 13. Physical device build

Use VS Code:

- Command Palette -> `Monkey C: Build for Device`
- choose Forerunner 965
- generate a signed `.prg`

Follow the detailed signing and sideloading instructions in `README.md`.

## Acceptance criteria

The MVP is complete only when all of these are true:

- [ ] Repository is a valid Connect IQ Watch Face project.
- [ ] Manifest targets Forerunner 965 only.
- [ ] Project builds successfully with the Garmin SDK.
- [ ] Simulator launches as a Forerunner 965.
- [ ] Time is the dominant central element.
- [ ] Time respects 12/24-hour watch setting.
- [ ] Date is displayed.
- [ ] Body Battery is displayed or safely shows `--`.
- [ ] Heart rate is displayed or safely shows `--`.
- [ ] Steps are displayed.
- [ ] Watch battery percentage is displayed.
- [ ] Black AMOLED background is used.
- [ ] Low-power mode is deliberately simpler than active mode.
- [ ] No seconds, animations, networking, settings, or non-MVP features are present.
- [ ] Developer key is not committed.
- [ ] Signed `.prg` can be copied to `GARMIN/APPS`.
- [ ] Aion can be selected and applied on the Forerunner 965.

## Suggested implementation order for the next model

Implement in this order and keep each step buildable:

1. project scaffold + manifest;
2. static black watch face with hard-coded sample text;
3. real time/date;
4. watch battery;
5. steps;
6. heart-rate complication;
7. Body Battery complication;
8. low-power behavior;
9. null/error handling;
10. final simulator/build cleanup;
11. update README only if actual implementation changes any command or path.

Do not expand the scope before the MVP has been physically sideloaded and used on the Forerunner 965.

## After the MVP

Only after the MVP works on the physical watch, possible later iterations include:

- better typography/layout;
- icons;
- color accents;
- configurable data fields;
- tap actions;
- further sleep/recovery metrics;
- Sleep Score if the Forerunner 965 gains a compatible Connect IQ API path;
- Connect IQ Store packaging.

Those are deliberately not part of the first implementation.
